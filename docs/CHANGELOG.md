## Phase 7

- 2026-09-09 [ERN-P7.8] `pnpm audit` cleared: 2 high and 2 moderate advisories, all transitive and none reachable from app code — `mysql2` (auth-plugin downgrade to `mysql_clear_password`, and an unbounded zlib inflate) and `deepmerge-ts` (stack exhaustion) through the `prisma` CLI, `uuid` (missing buffer bounds check) through exceljs. `pnpm update` could fix none of them (prisma 7.10.0 is the newest 7.x and pins `mysql2` at exactly 3.15.3; prisma 8 is a release candidate), so they are pinned with `pnpm.overrides`: `deepmerge-ts ^8.0.0`, `mysql2 ^3.23.1`, `uuid ^11.1.1`. Because `deepmerge-ts` crosses a major inside the tool that runs migrations, the whole production path was re-proven on an empty database afterwards (generate, `migrate deploy`, `sync-app-role`, seed, `migrate diff`, and `pnpm install --frozen-lockfile`). `pnpm audit --audit-level=moderate`: no known vulnerabilities.

- 2026-09-09 [ERN-P7.4] PWA: `app/manifest.ts` serves ER Navigator / "ER Nav" at `/manifest.webmanifest` (standalone, start url `/`, theme `#1f7a8c`, background `#f5f7f6`, 192 and 512 icons offered as both `any` and `maskable`); the icons are drawn in code by `scripts/generate-icons.mjs` — a white ring and two hands on a rounded square in the accent colour, supersampled and encoded with nothing but `node:zlib`, no image library and no template artwork; the root layout adds the manifest, icon, apple-touch-icon and iOS standalone metadata, and `proxy.ts` keeps all of those paths public because a phone fetches them before anyone signs in. The board gains a dismissible install banner: an Install button wired to the `beforeinstallprompt` event on Chrome and Edge, one line about Share → "Add to Home Screen" on iOS Safari, dismissal remembered in `localStorage` (a UI preference, the one thing the locked plan allows there, and never case data).
- 2026-09-09 [ERN-P7.3] CSP without `'unsafe-inline'` for scripts: the whole policy moves out of `next.config.ts` into `proxy.ts`, the only place that can mint a per-request nonce. Sixteen random bytes go onto the request as `x-nonce` and as `content-security-policy` (which is where Next reads the nonce for its own bootstrap scripts) and onto the response as the served policy; `script-src` is now `'self' 'nonce-…' 'strict-dynamic'` with `object-src 'none'` added. Verified: every `<script>` Next emits carries the nonce and the nonce differs per request (`tests/e2e/headers.spec.ts`). `style-src` keeps `'unsafe-inline'`, and only Recharts is why — measured by serving `style-src 'self'` and walking the app: the board, the case editor and the admin screens reported no violation at all, while `/dashboard` reported twenty inline-style refusals and rendered no chart, because Recharts sets `style="…"` attributes and a style attribute cannot carry a nonce.
- 2026-09-09 [ERN-P7.2] A refused page is a real HTTP 403: `experimental.authInterrupts` is on, `app/forbidden.tsx` is the body, and `requireAction()` calls Next's `forbidden()` after writing the `auth.forbidden` audit row. A VIEWER on `/cases/new` and a NAVIGATOR on `/export` or `/report` now get a status a proxy, a log and a monitor can see instead of a 200 whose body says no. Route handlers and server actions are unchanged.
- 2026-09-09 [ERN-P7.1] The alert directory moves onto the user record: `User.email` (nullable, unique, migration `20260909150000_user_email`), set and cleared from Admin → Users on create and per row, validated with zod (trimmed, lower-cased, max 254) and audited as `user.update` with the address in before and after. The alerts worker's recipients become the active SUPERVISOR and ADMIN rows that have one, read from the database every cycle, so a change on Admin → Users takes effect within an interval with no redeploy. `ALERT_EMAIL_MAP` and `parseRecipientMap()` are deleted outright — code, `.env.example`, compose passthrough, entrypoint allowlist and runbook. The PHI guard still reads only the `Case` model and now says why: `User.email` is contact data for a member of staff who signs in, never a patient's.
